Apply two LVS dual-write packages, not the full Microsoft list

Microsoft solutions still need to exist in Dataverse so tables, plugins, and map definitions are there. What floods the Dual-write page is Apply solution in Finance. If you only apply two LVS packages, only those maps get published.

Working note · September 2026 · Custom solution today: 29 customized maps in LVS Dual-Write Maps

The idea

Keep Dual-write Core and the Project Operations / Finance dual-write apps installed in Dataverse. In Finance, apply only LVS_Standard_Maps and LVS Dual-Write Maps. That matches how this customer uses the product: Project Operations synced from Finance and Operations, plus a small LVS customization set. Two apply steps, a short Dual-write list, and a unique search token still works when one map fails.

What to put where

One map belongs in one solution. Customized maps stay in the existing LVS package.

Customers V3, Contacts, Operating unit, and Projects V2 already live in the custom solution. Putting the Microsoft copy in LVS_Standard_Maps gives you the version pile you already have: four accounts - Customers V3 rows.

Build LVS_Standard_Maps from a working environment

Create the solution

In Power Apps, new solution, LVS publisher.

Add existing dual-write maps

Add existing → Other → Dual Write table map.

Take only required out-of-box maps

Add the latest version of each map you still run. Skip maps already customized in LVS Dual-Write Maps.

Include related maps

Add every related map you always keep checked in the Run dialog: company, currency, and ledger if Project Operations asks for it.

Export managed

Export as a managed solution so the target environment stays clean.

Import, then apply

Import into the target Dataverse environment. Then on the Dual-write page in Finance, apply LVS_Standard_Maps, then LVS Dual-Write Maps.

Watch-outs

Related maps

If Run asks for a related map that was never applied, start fails. Walk the Run dialog once in TSTDEP and add every related map you keep checked into LVS_Standard_Maps.

Microsoft map updates

New Microsoft map versions will not show up until you add them to LVS_Standard_Maps and re-export. Pin this to the Project Operations dual-write map release.

Install versus apply

Dual-write Core, and the Project Operations / Finance dual-write apps, still get installed in Dataverse. You are only skipping Apply of the big Microsoft map packages in Finance.

Health check warnings

Health check may warn that Microsoft map solutions are not applied. That can be ignored if the maps you run are Running and the link is healthy.

This is an operating pattern for environments rebuilt or refreshed from production, where Dual-write runtime is wiped and maps must be applied and started again. It does not start maps or run initial sync. It only shortens the list that has to be applied and found on the Dual-write page.
